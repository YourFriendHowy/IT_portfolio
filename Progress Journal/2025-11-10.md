#### Arch Linux Install
I have installed arch a few times now using the installation wizard. Today I challenged myself to Install and configure it using only the Arch wiki and forums if i must google. AI has been completely avoided for this VM
- **Struggles along the way**
	- My first speed bump was the locale configurations, I followed the steps as shown on the wiki and did a very basic initial config, that later threw errors after installation was complete. That will be discussed further down.
	- The second hurdle was Installing the essential packages, which i used the example basic install `# pacman -S /mnt base linux linux-firmware`. .
	- I did have some issues with fstab, I noticed i used pacman and not pacstrap, so I ran `# pacstrap -K /mnt base linux linux-firmware`, which permitted me to continue and got me past that small snag. I still don't know what pacstrap does, I should have a look. The wiki explains its basically pacman with the ability to point to a install directory.
	- Everyrthing went fine here for a while, `# ln -sf /usr/share/zoneinfo/_Region_/_City_ /etc/localtime` did throw me off, I typed it in exactly, then realized the intention may be for me to fill in region and city which became `# ln -sf /usr/share/zoneinfo/US/Michigan /etc/localtime`, I still not sure if I did that correctly though.
	- Everything else goes smooth, I decide to skip initramfs as it mentions it is already installed with kernal, I installed GRUB as my boot loader and reboot the system
#### The big oopsie
You notice above I only said I installed GRUB, I didn't configure it. So I sit at a checking for bootable disk screen for a while. I am going back and forth in my head, trying to figure out where I went wrong. This is the moment that I started to feel the pressure of using AI to solve this issue but I sat with it. I decided it was one of two things, I did my partitioning wrong or I didn't complete GRUB. So I go to the GRUB wiki and begin reading. I learn I used MBR and then there it was under installation, `grub-install --target=i386-pc /dev/sda2`. How in the hell do I fix this??? I slump in my seat thinking about having to go through the entire installation process, delete the vm and start over. Then I recall a sequence from the installation `mount /dev/_root_partition_ /mnt` so I reboot into live and mount the disk. from inside it I run the grub-install command. I get an ext2 error. I go into fdisk and start looking, trying some other partition configs, nothing is working. Oh! I need to unmount to do fdisk, so I unmount and go repartition and make a boot partition. Every try is a partition error of some sort. Finally I go back to the GRUB arch wiki page defeated and I start rereading through the partion instructions, and I get to installation again and read under the command "_where `i386-pc` is deliberately used regardless of your actual architecture, and `/dev/sdaX` is the **disk** (**not a partition**) where GRUB is to be installed._" Facepalm I have been running `grub-install --target=i386-pc /dev/sdaX`
adding partition numbers so i go back and run `grub-install --target=i386-pc /dev/sda`. Boom GRUB installs no error message. I umount and reboot, GRUB appears! Victory!

##### Why Arch?
Why not arch? Its notoriously difficult to learn with alot that the user needs to know to set it up correctly. As Im on a VM with limited storage I will need to learn to manage whats installed, remving whts not used and keepiong what is up to date. Its a bare bones OS, so all things dependencies, security, permissions, groups and users will need to be done manually. Its a great environment to learn how and what to automate. It has no bloat, so its less to learn immediately and allows for more of a waterfall exposure style of learning.
